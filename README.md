# iaeg2026-soft-soil-egm
Open-source soft-soil EGM workflow (GeoTOP, CPTs, GemPy, Speckle) for IAEG 2026.

Project home page with the model extent on a map: <https://bedrock-engineer.github.io/iaeg2026-soft-soil-egm/> (source in [`site/`](site/)).

## Local notebooks

Run `uvx marimo edit --sandbox --watch notebooks/01_get_data.py` to select data around the building footprint loaded from R2. The buffer is measured in RD New metres; touched GeoTOP columns define the exact area used to select CPTs and geotechnical boreholes from the BRO's REST API, by their delivered coordinates. Use the download button to create the local `data/` inputs: `geotop.nc` (all GeoTOP variables), `cpts.parquet` and `selection.json`. The notebook then writes the voxels as a bimpolars BimDataFrame, `geotop_bimdf.parquet`, and shows them in the GeoSpeckleViewer.

Run `uvx marimo edit --sandbox --watch notebooks/02_simulation_domains.py` to group the GeoTOP voxels into simulation domains: start from a preset, assign each GeoTOP unit to a domain, split by lithology or cut the model's base, and compare the domains' CPT coverage and qc/Rf distributions in tables, charts, linked cross-sections and 3D. Saving the domains writes their definition to `notebooks/simulation_domains.json`, which is committed and restored as the notebook's first preset, and the domain of each voxel and CPT sample to `data/voxel_domains.parquet` and `data/sample_domains.parquet` for the next notebook.

Run `uvx marimo edit --sandbox --watch notebooks/03_variograms.py` to fit variograms per simulation domain to the normal scores of one or more CPT parameters (log₁₀ qc, log₁₀ fs, Rf), optionally after removing each domain's linear trend with depth: vertically along the CPTs and horizontally between CPTs at one level. Exponential, spherical and Gaussian models are fitted for each parameter and domain; each domain starts with the one that misfits least and can be switched to another. Saving writes the variograms of all chosen parameters, in GSTools' terms, to `notebooks/variograms.json`, which is committed, for the simulation notebook. Each parameter's entry records when it was saved and the date of the simulation domains it was fitted on; the other parameters' entries stay as they were.

Run `uvx marimo edit --sandbox --watch notebooks/04_simulation.py` to simulate the CPT parameters in each simulation domain (only parameters whose saved variograms were fitted on the saved simulation domains and cover each of them): conditional Gaussian simulation of the normal scores with the saved variograms, on a grid whose horizontal (10–100 m) and vertical (10–50 cm) resolution divides the GeoTOP voxels, conditioned on the CPTs by simple kriging and transformed back with each domain's trend. The cross-sections of `02`, coloured by a realisation or a statistic, the reproduction of each domain's distribution and the realisations at a CPT show the result. Each run of a parameter is saved as soon as it is simulated, as NetCDF in `data/simulations/` (realisation × z × y × x, with each cell's domain and the run's definition), named by a hash of its definition: the parameter's variograms, the simulation domains, the resolution, the number of realisations and the seed. A run with the same definition is read from its file instead of simulated again.

Downloaded XMLs, GeoTOP voxels, CPT tables and selection manifests are generated locally and ignored by Git. No data directory is needed in a fresh checkout. The website loads its inputs separately from R2.
