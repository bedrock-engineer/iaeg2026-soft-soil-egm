# iaeg2026-soft-soil-egm
Open-source soft-soil EGM workflow (GeoTOP, CPTs, GemPy, Speckle) for IAEG 2026.

Project home page with the model extent on a map: <https://bedrock-engineer.github.io/iaeg2026-soft-soil-egm/> (source in [`site/`](site/)).

## Local notebooks

Run `uvx marimo edit --sandbox --watch notebooks/01_get_data.py` to select data around the building footprint loaded from R2. The buffer is measured in RD New meters; touched GeoTOP columns define the exact area used to select CPTs and geotechnical boreholes from the BRO's REST API, by their delivered coordinates. Use the download button to create the local `data/` inputs: `geotop.nc` (all GeoTOP variables), `cpts.parquet` and `selection.json`. The notebook then writes the voxels as a bimpolars BimDataFrame, `geotop_bimdf.parquet`, and shows them in the GeoSpeckleViewer.

Run `uvx marimo edit --sandbox --watch notebooks/02_simulation_domains.py` to group the GeoTOP voxels into simulation domains: start from a preset, assign each GeoTOP unit to a domain, split by lithology or cut the model's base, and compare the domains' CPT coverage and qc/Rf distributions in tables, charts, linked cross-sections and 3D. Saving the domains writes their definition to `notebooks/simulation_domains.json`, which is committed and restored as the notebook's first preset, and the domain of each voxel and CPT sample to `data/voxel_domains.parquet` and `data/sample_domains.parquet` for the next notebook.

Run `uvx marimo edit --sandbox --watch notebooks/03_variograms.py` to resample the CPT readings at a chosen height (10, 25 or 50 cm) and fit variograms per simulation domain to the normal scores of one or both CPT parameters that are simulated (log₁₀ qc and log₁₀ fs; Rf follows from them), optionally after removing each domain's linear trend with depth: vertically along the CPTs and horizontally between CPTs at one level. Samples and variograms are saved per height, and only hold at their own height. Exponential, spherical and Gaussian models are fitted for each parameter and domain; each domain starts with the one that misfits least and can be switched to another. Saving writes the variograms of all chosen parameters at the chosen height, in GSTools' terms, to `notebooks/variograms.json`, which is committed, and the CPT samples to `data/simulation_samples_<height>cm.parquet`, for the simulation notebook. Each parameter's entry records when it was saved and the date of the simulation domains it was fitted on; the other heights and parameters stay as they were. A table at the end lists all saved variograms.

Run `uvx marimo edit --sandbox --watch notebooks/04_simulation.py` to simulate the CPT parameters in each simulation domain (only parameters whose saved variograms were fitted on the saved simulation domains and cover each of them): conditional Gaussian simulation of the normal scores with the saved variograms, on a grid that divides the GeoTOP voxels, with a chosen horizontal resolution (10–100 m) and a vertical one from the sample heights saved in `03`, conditioned on that height's CPT samples by simple kriging and transformed back with each domain's trend. fs is co-simulated with qc (collocated co-simulation with Markov model 1, with each domain's correlation of their normal scores at the CPTs), so that each realization keeps their relation for a classification such as Robertson's; choosing fs simulates qc with it. Rf is not simulated: it follows from each realization's qc and fs. The cross-sections of `02`, colored by the median or spread (P90 / P10) of each simulated parameter or by simulation domain, stratigraphic unit or GeoTOP lithology class, the reproduction of each domain's distribution and the realizations at the CPT clicked in the cross-sections show the result. Each press of Simulate saves one run as soon as it is done, as NetCDF in `data/simulations/` (the chosen parameters per realization × z × y × x with their P10, P50 and P90 per cell, each cell's domain and the run's definition), named by a hash of its definition: the parameters' variograms, the simulation domains, the resolution, the number of realizations and the seed. A run with the same definition is not saved again, and a parameter simulated before with the same definition is copied from that run. The saved runs are listed under the Simulate form; the selected one, the latest after Simulate, is shown in the cross-sections and checks.

Run `uvx marimo edit --sandbox --watch notebooks/cpt_robertson_classification.py` to check `robertson`, the vectorized Robertson soil behavior type classification that the classification notebook imports, on the measured CPTs against GeoLibPlus and CEMS CPT Core. It needs Python 3.12 because of GeoLibPlus, and a NUCLEI token for CEMS CPT Core, which is not saved. Each CPT's CEMS request and raw response are saved in `data/cpt_robertson/cems/`.

Run `uvx marimo edit --sandbox --watch notebooks/05_cpt_classification.py` to classify each realization of a run with fs co-simulated with qc with `robertson`. Each run is classified once and saved as NetCDF in `data/cpt_classification/` on the run's grid, named after the run and a hash of the classification's definition: per cell the probability of each soil behavior type zone, the most likely zone and the P10, P50 and P90 of Ic. The ground level comes from the top of each GeoTOP column. The cross-sections of `02`, colored by the most likely SBTn zone, an SBTn zone's probability, Ic's median or spread or the simulation domain, show the result, with the CPT clicked in them plotted in its column of cells. The checks compare the zones' shares per domain with those of the CPT samples, the zones at the CPT samples, and the most likely zone with GeoTOP's lithology class. A last section compares the classified runs of the same horizontal resolution: the layers per 10 m of column and how likely their zones are, per domain and by the distance to the nearest CPT, against the layers of the CPT samples themselves.

Run `uvx marimo edit --sandbox --watch notebooks/06_bimdataframes.py` to turn a classified run into two BimDataFrames, written as GeoParquet to `data/bimdataframes/` in the same site CRS as the GeoTOP voxels: the interpreted CPTs, with consecutive samples of the same SBTn merged into one cylinder per layer (`cpts_interpreted_<height>cm.parquet`), and the SBTn volumes, with all cells of the same most likely SBTn merged into one surface with PyVista (`sbtn_volumes_<run>.parquet`), leaving out a pit where the CPTs and part of the foundations stand free. Each row carries the summary statistics of what it merges. It also writes Revit's advanced sample project in that CRS (`rvt_advanced_sample_combined_arch_str.parquet`). The GeoSpeckleViewer shows them among the 3D BAG's buildings, with the foundations of Revit's advanced sample project; checkboxes beside it show or hide each of these and, in a legend, each SBTn's volume. A last section publishes the volumes, the CPTs and the whole Revit model as new versions of models on a Speckle server when Publish is pressed, signed in with this machine's Speckle account or a token that is not saved.

Run `uvx marimo edit --sandbox --watch notebooks/sync_r2.py` to put one classified run on Cloudflare R2 for the GitHub Page, the 10 m / 25 cm run to start with: a Zarr group `soil_model.zarr/<height>cm/` on the run's grid with the P10, P50 and P90 of qc, fs and Ic, the most likely SBTn and the probability of each, the simulation domain and GeoTOP's stratigraphic unit and lithology class; a `soil_model_<height>cm.json` with the decisions behind it; the CPT readings in `cpts.parquet`; and the BimDataFrames of `06`, as `cpts_interpreted_<height>cm.parquet`, `sbtn_volumes_<height>cm.parquet` and `rvt_advanced_sample_combined_arch_str.parquet`. The first two are written to `data/r2/` first, and all go to R2 only when Push is pressed, with the R2 keys from the environment or the widget.

Downloaded XMLs, GeoTOP voxels, CPT tables and selection manifests are generated locally and ignored by Git. No data directory is needed in a fresh checkout. The website loads its inputs separately from R2.
